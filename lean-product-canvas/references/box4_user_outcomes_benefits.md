# Complete AI Prompts by Canvas Box
## Product Discovery for Agile Teams

This document organizes all AI prompts (Generation, Selection, and Review) by Lean Product Canvas box for easy reference.

---

## 🎯 Core Principle

**AI outputs are assumptions that must be validated, not facts to be accepted.**

Use these prompts to accelerate your discovery work, but always treat AI-generated content as assumptions requiring validation with real evidence.

---

## How to Use This Document

**Three types of prompts for each Canvas box:**

1. **GENERATION PROMPTS** (Optional)
   - Use when: You need ideas, are stuck, or want alternatives
   - AI does: Generates multiple options
   - You do: Evaluate and treat as assumptions

2. **SELECTION PROMPTS** (After Generation)
   - Use when: AI gave you too many options
   - AI does: Asks you questions about options
   - You do: Choose ONE focus + organize backlog

3. **REVIEW PROMPTS** (Recommended)
   - Use when: After you've completed work manually
   - AI does: Critiques format, clarity, identifies assumptions
   - You do: Revise your own work

# BOX 4: User Outcomes & Benefits (JTBD)

## Purpose

Define the most important outcomes users are trying to generate. Can use [Who] [Does What] [By How Much] format OR Jobs To Be Done framework.

---

## GENERATION PROMPT: User Outcomes (JTBD)

**When to use:** Identifying jobs to be done, understanding customer outcomes

```
I'm working on understanding user outcomes for the Lean Product Canvas.

Context:
- Target customer: [DESCRIBE CUSTOMER FROM BOX 3]
- Situation/context: [DESCRIBE WHEN/WHERE THEY USE PRODUCT]

Help me identify potential "jobs to be done" by:
1. Generating 5-7 jobs this customer might be trying to accomplish
2. For each job, identify the functional, emotional, and social dimensions
3. Suggest what evidence would indicate this is a real job vs. assumed job
4. Flag which jobs are most likely to be assumptions vs. validated needs

Include jobs that might not be obvious but could be important.
```

**Validation Required:** Conduct customer conversations to verify these are real needs, not assumptions.

---

## REVIEW PROMPT: User Outcomes (JTBD)

**When to use:** After you've defined user outcomes or jobs to be done

```
I've completed Box 4 (User Outcomes & Benefits) of the Lean Product Canvas. 
Please review my work and provide constructive feedback.

Here are my user outcomes/JTBD:
[PASTE YOUR USER OUTCOMES]

Context: This box defines the most important outcomes users are trying to generate. 
Can use [Who] [Does What] [By How Much] format OR Jobs To Be Done framework.

Please provide feedback on:

1. FORMAT ADHERENCE
   - If using outcome format: Does it follow [Who] [Does What] [By How Much]?
   - If using JTBD: Is it framed as a job the user needs done?
   - Are these outcomes or just features in disguise?

2. CLARITY
   - Are these written from the USER'S perspective (not ours)?
   - Do these represent what users are trying to achieve?
   - Are they specific enough to guide solution design?
   - Are they about user success, not product features?
   - Would users recognize themselves in these statements?

3. RISKY ASSUMPTIONS
   - Identify 2-3 assumptions about what users care about
   - For each assumption, note why it's risky if users don't actually want this
   - Suggest how to validate these are real user needs
   - Highlight gaps: what might we be missing about user needs?

Do NOT rewrite my user outcomes. Instead, provide specific guidance on how I 
can improve them myself.
```
